                - 💡 TIL: Ruby on Rails (Docker Compose環境) におけるDB接続エラーの根本原因今回のエラーは、Railsアプリケーション（webコンテナ）がデータベースコンテナ（db）に接続しようとした際に発生した**ActiveRecord::ConnectionNotEstablishedおよびcould not translate host name "db" to address**でした。この問題の根本原因は、単一の不具合ではなく、複数の設定ミスや不整合が段階的に問題を悪化させていたことにあります。根本原因の構造段階エラー/問題点根本的な原因第1の原因dbコンテナのRestarting（再起動の繰り返し）PostgreSQLデータボリュームの不整合と認証情報の不足。第2の原因ActiveRecord::ConnectionNotEstablishedが解消しない設定値の不一致とDB初期化の欠如。第3の原因docker compose downが失敗するdepends_onの記述形式の誤り。段階別 詳細な根本原因1. データベースコンテナ（db）の起動失敗最初の根本的な問題は、Railsアプリが接続する以前に、データベースコンテナ自体が稼働できていなかったことです。データボリュームの不整合:docker compose logs dbで確認された通り、PostgreSQLのDockerイメージが使用しているデータボリューム内に、以前のバージョンや不適切な形式のデータが残っていたため、コンテナが起動を拒否しRestarting状態を繰り返していました。解決策: 関連するDocker Volume (v3_runteq_mid_term_examination_rails_3_postgres_data) を完全に削除し、クリーンな状態で再起動しました。環境変数（認証情報）の不足:docker-compose.ymlのdbサービスに、Railsアプリのconfig/database.ymlで定義されている認証情報（username: root、password: password）やデータベース名が、PostgreSQLの環境変数として設定されていませんでした。解決策: dbサービスに**POSTGRES_USER**, POSTGRES_PASSWORD, POSTGRES_DB をdatabase.ymlと一致させて追記しました。2. ネットワーク/タイミングの問題（ホスト名解決エラーの再発）上記の修正後もcould not translate host name "db"が再発した際、一時的な問題として残っていた要因です。コンテナの起動順序:webコンテナが起動する際、dbコンテナがまだネットワーク上で完全に使用可能な状態になっていない（または、起動に時間がかかっている）状態で接続を試みたため、ホスト名が解決できませんでした。解決策: webサービスのdepends_onにdbを追加し、起動順序を制御することで、このタイミングの問題を解消しました。（最終的にはdbコンテナの健全性が確保されたことで解消しました。）3. 最後の接続後のエラー（最終確認）接続が確立可能になった後、最後に発生したエラーは以下の通りでした。ActiveRecord::PendingMigrationError:これはエラーではなく、データベース接続が成功した証です。アプリケーションが正しく接続でき、データベースが存在することを認識した後、テーブル構造の不一致（マイグレーションの未適用）を検知して発生しました。解決策: docker compose exec web rails db:migrateを実行し、データベースの構造を最新の状態にすることで、アプリケーションが正常に起動できるようになりました。まとめ今回のエラーの根本的な原因は、Docker Compose環境における**「DBデータボリュームの初期化失敗」と「Rails/Postgres間の認証情報およびDB名設定の不一致」**が同時に発生していたことでした。これらの問題を一つずつ修正し、最終的にマイグレーションを実行することで全て解消されました。
